2. CURRENT IMPLEMENTATION STATUS (WHAT WE ACTUALLY HAVE)
================================================================================
STATUS: Static, clickable prototype. Zero network calls. Zero persistence.

- src/App.tsx (1,259 lines) is a MONOLITH. Every page, layout, mock dataset and
  component lives in this one file.
- Mock data is hardcoded as module-level constants:
    * roomTypes: RoomType[]  (4 entries: deluxe, executive, standard, suite)
    * bookings:  Booking[]   (4 entries with reference IDs like DHI-2026-8F42K9)
- All "actions" are no-ops or client-only state:
    * Login = a role picker; no credentials; see LOGIN section.
    * Book / GuestDetails / Review / Confirmation = navigation only.
    * Lookup = local boolean toggle reveals a hardcoded booking.
    * Check-in / Check-out workflow = local `done` boolean.
    * Admin add/edit room = toggles a static form, no save.
    * Search/filter tables = client-side filtering of the mock array.
    * Export/print = window.print().
- Role is held in React state and inferred from URL prefix. No real auth.
- 49 shadcn/ui components under src/components/ui are present but NONE are
  imported by App.tsx (App uses raw HTML + custom CSS classes).
- No .env / .env.example, no API base URL, no fetch/axios wrapper, no query hooks,
  no DTO/type files, no service layer.

5. REQUIRED REST API — ENDPOINTS & DTO CONTRACTS
================================================================================
Conventions assumed:
- Base URL: /api/v1  (configurable via VITE_API_URL)
- Auth: Bearer JWT in Authorization header; role claims: guest/customer/
        receptionist/administrator
- All money: integer or decimal in NGN (bigint minor units NOT required by UI,
  but decimal with 2 places is recommended)
- Dates: ISO-8601 (YYYY-MM-DD for dates, full ISO timestamp for instants)
- List endpoints support: ?page=&pageSize=&q= (search) + domain filters
- Standard list envelope: { items: T[], total: number, page: number, pageSize: number }
- Standard error envelope: { error: { code: string, message: string, details?: any } }

   structured checkIn/checkOut/nights/rooms so the frontend can format them.
